# v1.5.3

> Backport release: this version cherry-picks the LiteLLM reranker SDK feature
> (#42) onto v1.5.2 without any other changes from `development`. No database
> migrations are involved; an in-place upgrade from v1.5.2 is supported.

### What's New

- **Rerank through a LiteLLM gateway.** The bridge gains an SDK-based reranker
  path: set `RERANKER_PROVIDER=litellm` with `RERANKER_MODEL` (e.g.
  `litellm_proxy/BAAI/bge-reranker-v2-m3`) plus `LITELLM_PROXY_API_BASE` and
  `LITELLM_PROXY_API_KEY` to route reranking through the same LiteLLM gateway
  already serving chat, vision and embeddings. The trailing `/v1` in the base
  is stripped automatically. This replaces the CPU-bound local reranker
  service for deployments without a GPU, cutting rerank latency from tens of
  seconds (or timeout fallback) to milliseconds.
- **Provider selection for reranking.** `RERANKER_PROVIDER` now selects the
  backend: `cohere` (alias `legacy_http`) keeps the previous HTTP behavior via
  `RERANKER_API_URL`/`RERANKER_API_KEY`, `local` runs a CrossEncoder in the
  bridge, and `litellm` uses the SDK path above. Unsupported values are
  rejected at startup.
- **Startup validation and fallback.** `RERANKER_MODEL` values that the pinned
  LiteLLM cannot route for reranking are rejected at startup instead of
  failing per query. `RERANKER_FALLBACK_MODEL` optionally designates a second
  `litellm_proxy/` alias on the same gateway as a single retryable-failure
  fallback (unset, blank or `none` disables it).
- **Standalone reranker service stays available.** The existing
  `hawki_rag_rerank` container keeps working unchanged (provider `cohere`,
  mode `external`); switching to `litellm` simply bypasses it.

### Internals

- New `hawki_reranking` package (`litellm_reranker`, `local_reranker`) wired
  into the bridge composition; reranker documents are extracted through a
  shared adapter. Benchmark tooling for rerank evaluation is included under
  `python_rag/benchmarks/rerank/`.
- Environment templates document the full reranker provider matrix, including
  the gateway variables and their defaults.

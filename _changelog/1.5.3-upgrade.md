# Upgrade to v1.5.3

## 1. Optional: route reranking through a LiteLLM gateway

No manual steps are required when upgrading from v1.5.2 — the database, the
legacy reranker configuration and all existing environment variables keep
working unchanged.

To switch reranking to a LiteLLM gateway (recommended for CPU-only hosts):

| Variable | Value |
|---|---|
| `RERANKER_MODE` | `external` (unchanged) |
| `RERANKER_PROVIDER` | `litellm` |
| `RERANKER_MODEL` | `litellm_proxy/<gateway-rerank-model>`, e.g. `litellm_proxy/BAAI/bge-reranker-v2-m3` |
| `LITELLM_PROXY_API_BASE` | Gateway base URL; a trailing `/v1` is stripped automatically |
| `LITELLM_PROXY_API_KEY` | Key for the gateway (independent of the chat/embedding `LITELLM_API_URL`/`LITELLM_API_KEY` pair) |

Notes:

- The gateway key variables are only read for `litellm_proxy/` models; hosted
  SDK providers use their own keys (e.g. `COHERE_API_KEY`).
- `RERANKER_API_URL` becomes unused with provider `litellm` and can be removed;
  the `hawki_rag_rerank` container can be stopped when nothing else calls it.
- Misrouted `RERANKER_MODEL` values now fail at bridge startup instead of
  per query — check the bridge logs first after switching.

## 2. Scope of this release

v1.5.3 is a backport of the reranker LiteLLM SDK feature (#42) onto v1.5.2.
It contains no database migrations and no model-provider environment changes;
`php artisan migrate --force` (run by the migrator service) is sufficient.

# v1.5.1

HAWKI RAG adds authenticated direct-text ingestion and safe source deletion,
with more reliable retries, indexing completeness checks, and clearer developer
and operator documentation.

### What's New

- **Direct text ingestion.** Submit plain text or Markdown through
  `POST /api/integrations/text-ingestions`, protected by a Sanctum personal
  access token with the `rag:text-ingest` ability and an explicit dataset
  ingestion grant. Laravel persists immutable Markdown artifacts and starts
  `IngestTextWorkflow`, which indexes the content without scraping or conversion.
  `202 Accepted` confirms asynchronous acceptance, not source readiness.
- **Safe direct-text deletion.** Delete a source through
  `DELETE /api/integrations/text-ingestions/{sourceId}` using the required token,
  dataset ingestion grant, and `Idempotency-Key`. The deletion flow cancels and
  waits for active ingestion before removing the source's Qdrant data and shared
  artifacts. It retains the source record as `deleted` for history and supports
  repeated deletion requests.

### Quality of Life

- **A clearer documentation handbook.** Improve installation, architecture,
  ingestion, retrieval, authorization, API, and operations guidance while
  preserving the existing documentation site's images, theme, and navigation.
- **Practical recovery guidance.** Add a worked example showing how to correlate
  Laravel callbacks and projected status, Temporal history, Qdrant vectors, and
  Neo4j facts before choosing a targeted recovery. Repository READMEs retain
  local development instructions and link to the handbook for system behavior.

### Bugfix

- **Incomplete indexing no longer appears complete.** Direct-text retries verify
  the expected chunk points and completion state instead of trusting a matching
  content hash alone. A failed chunk embedding fails the document before vector
  replacement, preventing a partially embedded source from being reported ready.
- **Stable source identity.** Direct-text document identity remains tied to its
  source rather than its descriptive URL. Documents sharing a URL no longer
  collide during incremental lookup or replacement.
- **Reliable workflow recovery and status.** Failed or uncertain direct-text
  submissions reconcile their stable workflow IDs. Task retries and recovery
  use the dedicated text workflow and persisted artifacts; terminal callbacks
  correctly project completion, and stale callbacks from earlier runs are ignored.
- **Worker-readable artifacts.** Shared directories and immutable files are
  published with the permissions needed by ingestion workers.
- **Metadata updates are retained.** Changes to direct-text metadata refresh
  Qdrant payloads and completion metadata without re-embedding unchanged content.
  Reordering metadata object keys no longer creates a false idempotency conflict;
  list order and compatibility with existing request hashes are preserved.
- **Stricter request and dataset validation.** Unknown top-level ingestion fields
  are rejected before side effects. Replays cannot bypass inactive-dataset checks
  or restart ingestion while the dataset is inactive.
- **Deleted sources stay deleted.** Late callbacks, old submission replays, task
  retries, and recovery jobs cannot revive a deleted source. Re-ingestion requires
  an explicit new submission with a new idempotency key. Failed deletion can be
  retried without discarding artifacts before Qdrant cleanup succeeds.

### Internals

- Add Laravel and Python request/workflow contracts, signed callback handling,
  OpenAPI definitions, and focused tests for direct-text submission, incremental
  indexing, recovery, authorization, and deletion.
- **Explicit model contracts.** Remove the bridge `GET /config` endpoint and
  Python-side model-selection environment fallbacks. Laravel supplies provider
  and model selections with each request. Ingestion workflow payloads require
  `ingestion.graph_model` and `ingestion.vision_model`; bridge `/query` requests
  require `provider`, `chat_model`, and `vision_model`.

  Clients calling the bridge directly must provide these fields; missing values
  fail validation rather than falling back to environment defaults. Startup
  checks cover Qdrant and Neo4j rather than probing a default model provider.
  Endpoint and authentication variables remain unchanged.
